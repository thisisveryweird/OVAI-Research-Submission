## Principal findings
1. **Clean recovery logic is stronger than its exported provenance.** `scripts/reproduce_original_historical_clean.py::recover_historical_sample_order`, lines 470–671, interprets numeric Dataset-2 headers as Cohort-2 workbook positions, checks precisely 1–55 and 57–120, checks all 60 explicit E-samples against Cohort 1, requires 179 unique IDs, excludes numeric position 56 and explicitly retains E-1056. This is a *conditional primary-header recovery algorithm*, not evidence that these input files were supplied or the mapping succeeded. Its own `main` results lines 1689–1694 instead claim 120+59 and E-1056 exclusion; terminal text lines 1760–1770 repeats the exclusion. `save_mapping`, lines 1313–1327, marks positions <=120 as Cohort 2 although recovery yields only 119 numeric columns: the first E-sample is mislabeled. `load_dataset2`, lines 736–759, retains obsolete 120/59 positional commentary and its nonfatal 1..120 audit contradicts the stronger upstream checks.
2. **Standalone still requires the superseded structure.** `scripts/reproduce_original_historical_standalone.py::load_dataset2`, lines 260–707, requires first 120 headers exactly 1..120 (roughly 431–497), then concatenates all 120 Cohort-2 workbook IDs with 59 trailing explicit IDs (519–523). It therefore cannot accept the clean script's asserted 119+60 structure. Cohort-1 workbook size is checked, but its explicit ID set/order is not validated against the trailing headers. Its decision not to exclude E-1056 does not repair numeric-header mapping.
3. **Older historical-data variant combines incompatible assumptions.** `scripts/reproduce_original_pmml_historical_data.py::get_processed_sample_order`, lines 171–293, drops E-1056 and assumes 120+59. `load_supplemental_dataset_2`, lines 301–1080, heuristically ranks sample-like header rows, translates only exact 1..179 or first-120 1..120 patterns, and otherwise calls headers explicit. Numeric positional values can then remain mistaken for biological IDs. The mixed branch demands trailing IDs exactly match workbook order (lines 694–731). `verify_against_processed_data`, lines 1084–1191, checks the old expected set and exact supplied order, despite commentary saying datasets may differ in order. None of these checks independently establishes true patients without primary workbooks.
4. **Benchmark variant does not recover IDs.** `scripts/reproduce_original_pmml.py::load_dataset`, lines 160–194, merely loads the processed benchmark's sample_id/diagnosis/binary_label and feature columns. It does not verify 179 rows, uniqueness, primary header mapping or endpoint label validity. Its warning that these are the same 179 historical patients (`main`, lines 1210–1240) is framing, not an enforced identity test. Previous raw-representation AUC 0.451682/sensitivity 0/specificity 1 is quoted in the historical-data script's docstring lines 10–14, not newly measured here.

## Output semantics and normalization
Across variants the asserted model is 14 inputs → 7 tanh → 2 tanh. Neuron 21 is asserted cancer, neuron 22 controls/borderline. Cancer=1; benign, borderline and control=0 in clean `load_labels` lines 1027–1070 and standalone `main` lines 1480–1525. The other variants trust stored binary_label.

Classification is **cancer activation > noncancer activation**, with exact ties assigned noncancer; the sign of activation 21 alone is not the rule. Higher cancer activation is used as the positive-oriented AUC score. Negative tanh values are legitimate activations, not negative probabilities. Outputs need not sum to one; `(score+1)/2` or softmax would be additional transformations, not demonstrated original calibrated probabilities. The benchmark script explicitly disclaims these probability interpretations at lines 28–48 and implements the rule in `main` lines 958–1039. Clean `forward_pass` lines 1216–1279 and standalone `forward_pass` lines 1071–1287 implement affine inputs and tanh layers. Approximate tie reporting in clean does not alter its strict decision rule.

Frozen normalization is x*scale+shift, not newly estimated cohort min-max scaling. Clean `verify_normalization` lines 1125–1209 checks embedded endpoint constants map to 0 and 1; benchmark `extract_normalization` lines 214–413 verifies LinearNorm slope/intercept and feature names. Standalone parses XML and checks endpoints in `parse_pmml`/`forward_pass` lines 773–1290, but class meanings are hardcoded assertions rather than parsed NeuralOutputs mappings. Historical-data `load_pmml_parameters` lines 1194–1373 trusts zipped feature/input order and layer order without equivalent endpoint, name or activation checks. Clean embeds parameters and does not require the original XML, so actual fidelity to that XML remains unverified here.

## Frozen vs transductive representation; leakage boundary
None of these four scripts trains a model or fits batch correction, imputation or normalization on new rows. Their neural forward passes are frozen and row-wise given a fixed representation. However three consume an already **batch-adjusted log10** historical supplementary matrix: frozen weights do not make upstream cohort-derived batch preprocessing prospective or leakage-free. The primary batch-adjustment recipe, fit population, stored fit parameters and original split assignments are missing. If adjustment was fit jointly across train/test or a full evaluation batch, information from evaluation expression distributions enters the representation (transductive preprocessing), unlike a training-only fitted transform applied unchanged to held-out individuals. These files neither establish nor remedy that boundary. The benchmark variant consumes a separately processed matrix; the historical-data docstring suggests raw TPM was previously supplied. Affine PMML scaling cannot turn raw TPM into the required historical batch/log representation.

## Portability and static defects
All four set `ROOT = Path.home() / "ovarian-ai"` (clean:43; standalone:67; benchmark:69; historical-data:72), rather than repository-relative/config-driven inputs. File names are explicit at their PATHS blocks. Clean requires supplementary workbook, GEO full metadata and both cohort workbooks; standalone additionally requires Source-code1.xml. Benchmark requires processed benchmark and deep-audit JSON; historical-data additionally uses current processed metadata and raw workbooks. Outputs also target the home-root, not this checkout. Choosing a canonical version requires fixing provenance contradictions, not merely naming the newest script.

Clean `main` lines 1491–1509 imports nonexistent standard sklearn.metrics sensitivity_score and specificity_score together with valid metrics; ordinary sklearn consequently triggers ImportError and sets roc_auc_score=None, leaving AUC unavailable while manual confusion metrics still work. No runtime test was performed. Clean `load_labels` requires only title/diagnosis but later selects stage/histology too (lines 958–968,1013–1023), so missing optional-looking columns fail. Benchmark's zip normalization extraction lacks an explicit input-count check; historical-data has weaker parameter validation still.
