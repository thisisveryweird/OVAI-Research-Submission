5. Rigor Already In Place (worth highlighting to

judges)

Not everything here is a gap. Several choices reflect real methodological maturity and are worth
stating explicitly rather than assuming judges will notice them in the code:

     ●​ Canonical evaluators use nested cross-validation (outer 5-fold for the reported metric, inner
          3-fold for hyperparameter selection) with fixed seeds, rather than a single train/test split.

     ●​ A hard rule against fabricating multimodal patient rows across unrelated studies is written
          into the README and enforced by validation checks in the data-loading code.

     ●​ CPTAC proteomics was investigated and explicitly declined as a fusion source because no
          verified patient-level, blood-specimen link to GSE94533 exists — a disciplined "no" that

PAGE 08

          many teams under deadline pressure would not have made (see
          reports/cptac_acquisition_audit.md).
     ●​ 58 candidate external GEO cohorts were systematically screened against platform, specimen,
          and phenotype criteria, with the screening logic and rejection reasons saved
          (reports/potential_external_datasets.md, reports/remaining_queue_screen.md).
     ●​ Borderline tumors are kept as their own category rather than being folded into either
          "cancer" or "non-cancer" for convenience — clinically correct, since borderline ovarian
          tumors are a genuinely distinct, non-invasive entity.

Phase 0 — Before the submission deadline (days)

     1.​ Pick one canonical headline result and present the full endpoint table from Section 4 next to

     3.​ Run a decision curve analysis (net benefit vs. threshold probability) for the production model

1.3 [Moderate] The two interaction terms in the production model add ~0.0003
AUC and trade sensitivity for specificity

From the same reports/high_capacity_model_results.md table: the simpler model without interaction
terms ("frozen_logistic": Top-5 signature + Age + CA-125 only) scores ROC-AUC 0.8994, balanced
accuracy 86.6%, sensitivity 84.6%, specificity 88.5%, versus the shipped model with two interaction
terms at ROC-AUC 0.8997, balanced accuracy 86.4%, sensitivity 82.7%, specificity 90.2%. The
interaction terms buy essentially no discrimination and cost ~2 points of sensitivity for ~2 points of
specificity. For a cancer-detection use case, a missed cancer (false negative) is a materially worse
error than an unnecessary referral (false positive), so the simpler, higher-sensitivity model is arguably
the clinically preferable choice, not the one currently in production_artifacts/. Recommend revisiting
which of the two gets deployed, and stating the sensitivity/specificity tradeoff explicitly rather than
only the AUC when justifying the choice.

2. Leakage / Validity Findings (confirmed by direct

code review, summarized from the internal audit)

These were independently re-verified by reading the relevant scripts rather than only trusting the
audit's prose — all confirmed accurate:

     ●​ [Moderate, confirmed] evaluate_gse94533_diagnostic_model.py and the methylation evaluator
          filter out non-informative feature columns (notna().any(), nunique() > 1) computed on the full
          frame before the outer CV split. This uses unlabeled information from held-out rows. It is a
          small leak (unsupervised, doesn't touch labels) but is real and easy to fix by moving the filter
          inside each fold.

     ●​ [Critical, confirmed] GSE106817/GSE113486/GSE113740 all show 0% sensitivity at the frozen
          decision threshold, with high apparent "accuracy" driven entirely by class imbalance (each
          cohort is 85–90%+ non-cancer). Ranking ability (AUC 0.77–0.83) is real; classification at the
          frozen threshold is not currently usable. Confirmed directly in
          reports/bulk_external_test_results.md, reports/gse106817_platform_shift_audit.md, and
          reports/gse106817_phase5.md.

PAGE 18

     ●​ [High, confirmed] No committed evidence recovers the original historical eLife 135/44
          patient train/test split; search_possible_historical_test_splits.py samples 20,000 candidate
          44-patient splits and explicitly documents that matching the published AUC does not prove a
          candidate is the real split. The historical ">80% independent-test" claim should not appear in
          competition materials as a validated result.

     ●​ [Confirmed] TCGA-OV stage endpoint (Stage I/II vs III/IV) scores below its own
          majority-class baseline (78.9% vs. 92.6%) with balanced accuracy 53% and AUC 0.49 —
          essentially uninformative. This must never be cited as evidence the project can detect cancer;
          it's a different, currently-unsuccessful question (staging, not detection) that happens to reuse
          a related data source.

3. Software Engineering and Reproducibility (new

findings)

3.1 [High] No version control in the delivered project

git log on the delivered codebase returns "not a git repository." There is no commit history, so there
is currently no way to show which exact version of the code produced any given number in a pitch deck,
no diff history, and no way to recover an earlier state if something regresses. Recommend initializing
git immediately, committing the current state, and tagging the exact commit used to generate every
number that goes into competition materials. This is a five-minute fix with outsized credibility value
if a judge or investor asks "can I see how this evolved?"

3.2 [Moderate] No LICENSE file

There is no LICENSE anywhere in the repository. Whether this should be permissive open-source, a
restrictive/proprietary license, or something in between is a business decision for the team (tied to
whether they want to show code publicly on the investor track), but the current state (no license at
all) defaults to "all rights reserved" with no clarity for collaborators or judges who may want to
inspect the code.

3.3 [Moderate] No automated tests beyond one manual smoke script

scripts/smoke_test.py is the only test in the repository, and it only checks that the untrained
multimodal architecture runs and its masking behaves on random tensors — there is no tests/
directory and no pytest usage anywhere. For a project whose core claims rest on "no leakage, no
fabricated multimodal rows," a small suite of automated guardrail tests would materially strengthen

HE4 is a component of both ROMA and Overa, the two most relevant FDA-cleared comparators. Its
absence means the project currently cannot run a direct, apples-to-apples comparison against either.
This is the single most valuable near-term data-acquisition target — recommend actively sourcing
an HE4-linked serum cohort, or prioritizing HE4 collection in any prospective data-collection effort.

4.2 [Notable, biologically grounded] False negatives cluster in

clear-cell/endometrioid histology, with lower miR-200 family expression

reports/error_analysis.md shows false negatives across every model variant are disproportionately
Endo/Clear Cell histology, and the largest expression contrasts between false negatives and
correctly-classified cancers are consistently in hsa-miR-200c-3p, hsa-miR-200a-3p, and
hsa-miR-29a-3p — all lower in the missed cases. This is not a data artifact; it tracks with published
biology: the miR-200 family is tied to epithelial-mesenchymal-transition signaling that is most active
in high-grade serous carcinoma, and clear-cell/mucinous histologies are already independently
known in the literature to be less well served by CA-125. Recommendation: report performance
stratified by histologic subtype as a standing, first-class metric (not just an appendix analysis), and
name "does this generalize across histologic subtype" as its own explicit open question in
competition materials rather than letting it be smoothed over by the aggregate cancer-vs-non-cancer
number. This is a genuine, well-supported scientific insight worth foregrounding — it will read well
to a judge with clinical background.

4.3 [Low] Stage I cannot currently be evaluated separately from Stage II

The current GSE94533 metadata group Stage I and Stage II together; every attempt to isolate Stage I
alone reports "insufficient class variation." Since Stage I is the highest-value detection target
clinically (the point at which 5-year survival is ~90%+), this is worth flagging as a specific
data-acquisition or metadata-refinement goal rather than leaving it implicit.

4.4 [Low] CA-125 missingness

CA-125 is missing in roughly 60 of 179 patients (~34%); Age is missing in 1 of 179. Imputation is
handled correctly (fold-contained), but given CA-125 is a primary driver of the "combined" model's
lift over miRNA-alone, this missingness rate is worth disclosing prominently rather than only in a
data-quality appendix.

seen real data

learned gates, explicit missing-modality masking), but it has only ever been run against torch.randn

8. Longer-Horizon Suggestions (not urgent for the

pitch, good research directions)

     ●​ Benchmark against other published circulating-miRNA ovarian cancer panels in the
          literature, not only the project's own historical signature, to contextualize where this
          signature sits relative to the field.

     ●​ Add probability calibration (Platt scaling or isotonic regression) on top of the existing
          logistic pipeline before any clinical framing of the output probability as a literal risk
          percentage.

     ●​ Treat the platform-shift finding (Section 2) as the project's central scientific result, not a side
          note: across three independent external cohorts, ranking ability survives (AUC 0.77–0.83) but
          absolute-scale classification does not — this is a genuinely useful, generalizable finding
          about circulating-miRNA biomarkers across sequencing/array platforms, and is arguably
          more publishable and more interesting to sophisticated investors than the internal accuracy
          number itself.

     ●​ Given how consistently every purely statistical fix attempted so far (rank transforms,
          pairwise ratios, quantile normalization) has failed to rescue external performance, the most
          credible path forward is prospective, harmonized, multi-site data collection rather than
          further post-hoc correction of already-collected, heterogeneous public data. This should be
          the team's central "ask" for both funding and expert clinical collaborators.
