### inference-final
# Final inference audit

Scope: six named scripts, two portal launchers and production JSON/binaries. Static review only; no application execution, imports of project code, model loading, installs or network. Full extracted source was read in `../inference-review/evidence.json`; this is not a full-repository audit. Folder date is a label, not verified execution chronology.

## Findings

1. **Evaluator and deployed transformations differ for missing clinical values.** `test_high_capacity_models.py::engineered_frame` multiplies log-miRNA by raw clinical values; `run` constructs these frames before `base_pipeline` median-imputes each column. A missing CA-125 therefore yields a missing product later replaced by the training-fold median product. `export_production_pipeline.py::transformed_values` instead median-imputes clinical values first, then multiplies each patient's log-miRNA by that median. `ovarian_diagnostic_portal.py::build_model_input` follows export order. These are not generally equivalent. The evaluated engineered model's metrics cannot simply certify the deployed missing-data transformation. Complete observed values avoid this specific difference; fold-fitted versus full-training fitted medians remain distinct by design.
2. **CLI is not the portal path.** `predict_ovarian_risk.py::main` creates seven columns, no interactions, and never reads the manifest; portal creates nine ordered columns. Default artifact filenames match, but `--artifact-dir` permits another model/scaler/default set. Against a nine-input scaler this CLI is dimensionally incompatible; no inference was executed to verify the runtime exception. Its confidence flag is max(p,1-p), not validated calibration or uncertainty.
3. **Invalid, missing and negative input policy differs.** Portal `read_uploaded_table` coerces malformed values to NaN. `build_model_input` rejects nonfinite/negative miRNAs, so malformed or absent panel measurements fail the entire batch; missing/nonfinite clinical values use defaults. Finite negative age/CA-125 in uploads are accepted, although manual widgets disallow negatives. Export clips negative miRNAs to zero, coerces clinical strings and median-imputes before products. CLI `parse_number` accepts named missing tokens but rejects other nonfinite numbers, clips negative miRNAs and fills clinical NaNs; it leaves miRNA NaNs unresolved and accepts finite negative clinical values. Zero is a real measurement, not missing.
4. **CSV/XLSX orientations and duplicate ambiguity.** Portal `normalized_label` strips all non-alphanumerics and lowercases. `read_uploaded_table` prefers patient-per-row when all five panel labels match columns; otherwise the first column becomes feature labels, remaining columns become patients. Dictionary comprehensions silently choose the last normalized duplicate column or feature row. Distinct spellings can collide; no duplicate-normalization rejection exists. Missing clinical labels become NaN, missing panel labels cause error. Patient IDs are not uniqueness-checked. XLSX uses openpyxl; CSV uses pandas defaults. No uploaded fixture was run.
5. **Manual defaults can look like measured data.** `sidebar_inputs` starts all five miRNAs at zero; age/CA-125 start at frozen medians (JSON: 55.5 and 87.2). Pending checkboxes replace clinical values with NaN and display a default caption; unchecked median-valued inputs are indistinguishable from measurements. Bulk output has only ID, probability and status, not imputation flags or effective inputs.
6. **Stale result risk, not a patient snapshot.** Portal `main` stores only `st.session_state['probability']` after successful manual execution. It stores no input snapshot, patient ID, artifact hash or timestamp, and does not invalidate probability when inputs change or an assessment fails. The old probability is rendered with the current manifest on later reruns. Bulk results are recomputed rather than stored in this key. No persistent prediction audit log is implemented in the reviewed portal.
7. **Hardcoded operating point and benchmarks.** `render_result` embeds 86.43% balanced accuracy, 82.70% early-stage sensitivity and 90.20% surgical specificity; these are not obtained from the loaded artifact or recomputed. Manual/bulk/CLI and evaluator use 0.5. Portal shows endpoint and training N in separate UI elements, but the benchmark cards do not provide validation design, denominators, external limitation or calibration evidence. 'Actionable Stage I/II' and 'Malignancy Probability' are stronger clinical interpretations than this static audit establishes.
8. **Research demos are stored-result displays, not fresh prediction.** `ovarian_research_demo.py` reads Age + 192-miRNA OOF CSV under `Path.home()/ovarian-ai`, states five-fold OOF and research-only use, and selects correct cases for display. `demo_ovarian_cases.py::main` reads historical 14-miRNA OOF CSV, checks 179 rows and required columns, likewise displays correct cases and a research disclaimer. Its lookup comprehension uses undefined `x` (`str(x): row`), so lookup construction would fail unless an unrelated global supplied it. Neither demo establishes new-patient performance or portal artifact validity; home-relative paths may target another checkout.
9. **Launchers install before serving.** Both root launchers invoke pip against requirements then run the portal. They were read only, never invoked. They do not launch the CLI or research demos.
