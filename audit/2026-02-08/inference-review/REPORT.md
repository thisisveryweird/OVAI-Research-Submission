## Proposed tests and affected repair choices (not executed)

- Shared pure preprocessing component used by exporter, portal, CLI and benchmark; choose either nine-feature engineered model or deliberately re-exported seven-feature model, never trim features to silence scaler errors. Contract test manifest order, model/scaler dimensions and clinical order.
- Golden synthetic cases: zero/positive miRNA, negative/NaN/infinite values, malformed numeric strings, missing age/CA-125 and bounds; assert consistent rejection/imputation and identical scalar/batch/CLI feature vectors. Interaction missingness test must distinguish product-of-imputed-input from median-of-products.
- Portal result-state tests: evaluate A then edit to B; failed B; change artifacts; upload/remove batch; ensure old result disappears or visibly retains evaluated A fingerprint. Add snapshot/artifact hash, timestamp and imputation flags without exposing unnecessary patient data.
- Upload parser tests: both orientations, normalized duplicates, repeated patient IDs, empty tables, omitted clinical fields, missing miRNA, invalid cells. Choose all-or-nothing versus explicit per-row error output; do not silently default malformed clinical data without flagging.
- Demo tests: replace undefined lookup key with explicit sample_id, ensure ID uniqueness; make research demo import-safe; configurable root. Maintain research-only wording and separate historical endpoints.
- Export tests: require patient-ID column, enforce binary labels and diagnosis concordance, reject duplicates rather than hiding them, hash exact source; clinical medians must be fit inside evaluation training folds. Add feature-selection provenance review before claiming unbiased performance.
- Launcher choice: separate documented environment setup from offline launch; preserve installation errors, use pinned environment and artifact dependency snapshot. Clinical wording requires research-only restriction pending validation, not merely a UI rewrite.
